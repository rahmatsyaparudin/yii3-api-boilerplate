# v1.2.1 — 2026-11-11

### Fixed
- **`QueryConditionApplier` — filter LIKE/ILIKE tidak pernah match.**
  `andLike()`/`orLike()` meneruskan operator `'ilike'` mentah ke
  `andWhere()`, padahal `'ilike'` tidak terdaftar di `conditionClasses`
  yiisoft/db — condition jatuh ke `SimpleBuilder` yang meng-bind value
  apa adanya (tanpa wrap `%value%`, tanpa escaping) → `ILIKE 'x'`
  (exact match). Semua kondisi kini dirutekan lewat `like`/`not like`
  agar `LikeBuilder` yang melakukan wrap + escape; case-insensitive
  dinyatakan lewat operand `caseSensitive` yang diubah builder pgsql
  menjadi `ILIKE` (driver lain mengabaikannya — `null` tetap perilaku
  default collation).
- `filterByLike()` — default `autoWrap` `true` → `false`. Wrap manual
  `'%'.$value.'%'` di-escape oleh `LikeBuilder` menjadi literal
  (`LIKE '%\%x\%%'` → selalu 0 row); value mentah kini diteruskan ke
  builder yang wrap sendiri. Helper privat baru
  `normalizeLikeOperator()`; docblock `andLike`/`orLike`/`filterByLike`
  diperbaiki (contoh tidak lagi memakai pola `'%…%'`).
- `ServiceTokenRepository::list()` — `filterByLike()` kini dipanggil
  dengan `autoWrap: false` + `db: $this->db` (resolusi `ilike` pgsql),
  dan `count()` di-cast ke `(int)`. `username`/`name` LIKE kembali
  match (mis. `'Dep'` → `ILIKE '%Dep%'`).
- Efek samping positif: `orLike` di `ExampleRepository` /
  `AnotherExampleRepository` yang mengoper value mentah sebelumnya
  menghasilkan exact-match `ILIKE 'x'` — kini `ILIKE '%x%'`.

### Catatan migrasi (project konsumen)
- Jangan lagi mengoper pola `'%term%'` ke `andLike`/`orLike`/`filterByLike`
  — karakter `%` akan di-escape menjadi literal. Oper value mentah;
  builder yang membungkus `%value%` sekaligus meng-escape wildcard.
