# v1.3.0

> Sync v2 foundation: opt-in column contract, global record identity,
> store provenance, doc_role edit rules, and a `sync_queue` outbox —
> plus the `SyncExample` reference module. Fully backward compatible:
> existing `origin_id`/`sync_flag` tables and the point-to-point
> SyncFlag flow keep working unchanged.

## Unreleased - 2026-11-26

### Added
- `src/Domain/Shared/Core/ValueObject/SyncIdentity.php`: immutable VO
  for the sync identity columns — `uuid` (auto-generated v4 via
  `random_bytes`, no external lib), `source_store_id`, `doc_role` —
  with `local()`/`copy()`/`interstore()` presets, `fromArray()`/
  `fromEntity()` hydration, `isEditableByUser()` (only `LOCAL`),
  `isOwnedBy()` (applier anti echo-loop), `isValidUuid()`.
- `src/Domain/Shared/Core/Enum/SyncQueueStatus.php`: backed int enum —
  `PENDING` (1), `SENT` (2), `ACKED` (3), `FAILED` (4) — with
  `fromValue()` (throws via `sync_queue.invalid_status`) and `label()`.
- `src/Application/Shared/Core/Factory/SyncIdentityFactory.php`: builds
  `SyncIdentity` stamping `source_store_id` from params `app/sync`
  (env `app.sync.store_id`; `0` = cloud/master, `>0` = store id);
  `incomingCopy()`/`incomingInterstore()` for the applier,
  `isOwnRecord()` echo-loop guard, `assertEditableByUser()` (throws
  `doc_role.not_editable`).
- `src/Application/Shared/Core/Factory/SyncOutboxFactory.php`: builds
  `sync_queue` row arrays (`buildRow()`/`buildRows()`/broadcast via
  `destination_store_id = null`) for repositories to insert in the same
  transaction as the business write (outbox pattern).
- `src/Migration/Sync/M20261126000000CreateSyncQueueTable.php`:
  `sync_queue` outbox table — one row per record per destination with
  status/retry/ack tracking.
- `AppConstants`: `UUID`, `SOURCE_STORE_ID`, `DOC_ROLE` field constants.
- Params `app/sync` (`store_id`) in `params-core.php` and
  `app.sync.store_id` in `.env.example`.
- Validation messages `doc_role.not_editable` and
  `sync_queue.invalid_status` (en + id).
- `tests/Unit/Domain/Shared/Core/ValueObject/SyncIdentityTest.php`.
- `SyncExample` module (`sync_example` table) — reference
  implementation of the full sync scheme end-to-end: migration uses
  `...SyncColumns::all($cb)`; entity carries both `SyncFlag` and
  `SyncIdentity`; `create()` stamps `SyncIdentityFactory` and writes
  the record + `sync_queue` rows in one transaction via
  `insertWithOutbox()`; `update()`/`delete()` enforce
  `assertEditableByUser()` (doc_role guard); repository adds
  `findByUuid()`. Routes `/v1/sync-example/*`, permissions
  `sync-example.*`.
- `SyncColumns::mongodb()` group (`sync_mdb`) and canonical tail order
  in `all()`: `lock_version → sync_mdb → sync_flag → origin_id →
  source_store_id → uuid → doc_role` (write `detail_info` manually
  before the spread).

### Changed
- `config/common/di/service-di.php`: `SyncIdentityFactory` bound with
  the `app/sync` params group.
- `config/common/routes.php`, `config/common/access.php`,
  `config/common/repository.php`: SyncExample registrations.
- `scripts/skeleton-copy-examples.php`: `SyncExample` subtree added so

## Unreleased - 2026-11-18

### Added
- `src/Shared/Core/Enums/SyncColumns.php`: opt-in column contract for
  sync-aware tables — `identity()` (`uuid`, `source_store_id`),
  `routing()` (`origin_id`, `sync_flag`), `locking()` (`doc_role`,
  `lock_version`), `all()`, and `names()`; spread into
  `createTable(..., [...SyncColumns::all($cb)])` or looped into
  `addColumn()` for ALTER migrations.
- `src/Domain/Shared/Core/Enum/DocRole.php`: string-backed enum —
  `LOCAL` / `INTERSTORE` / `COPY` — with `fromValue()` (throws
  `BadRequestException` via `doc_role.invalid_value`) and `label()`.
- `src/Console/Core/SyncColumnsCommand.php` + `sync:columns` command:
  - `sync:columns add <table> <Module>` generates an ALTER migration
    looping `SyncColumns::all($cb)` via `addColumn()` / `dropColumn()`.
  - `sync:columns inject <file>` inserts `...SyncColumns::all($cb),`
    plus the `use` statement into an existing create-table migration,
    verifies `php -l`, and auto-reverts on invalid output (idempotent).
- Validation message `doc_role.invalid_value` (en + id).

### Changed
- `config/console/commands.php`: registered `sync:columns`.
- `docs-guide/22-sync-flag-guide.md`: documented the `SyncColumns`
  contract, both command modes, and the `uuid` backfill caveat for
  populated tables.

### How to apply this update
1. Run `composer skeleton:update` to sync the new Core VOs, factories,
   enums, params, messages, and the `sync:columns` command.
2. Run `php scripts/skeleton-copy-examples.php` if you want the
   `SyncExample` reference module (routes/permissions must be copied
   manually or re-merged — they are not auto-synced).
3. Run the `Sync` migrations (`migrate:module sync` or equivalent) to
   create `sync_queue` and `sync_example`.
4. Set `app.sync.store_id` in `.env` per instance (`0` = cloud/master,
   `>0` = store/origin id).
5. Existing tables stay unchanged; opt in per table via
   `yii sync:columns add <table> <Module>` or spread `SyncColumns::all()`
   in a new `createTable()` — backfill `uuid` on populated tables.
