# Localization and Internationalization Guide

## 📋 Overview

This guide covers the localization and internationalization (i18n) system in the Yii3 API application. The system uses `yiisoft/translator` with PHP-array message sources, supports multiple languages, and provides structured message files for different types of application messages.

---

## 🏗️ Localization Structure

### Directory Structure

```
resources/messages/
├── en/                    # English messages
│   ├── app.php            # Project-owned application messages
│   ├── error.php          # Error messages (skeleton-managed)
│   ├── success.php        # Success messages (skeleton-managed)
│   └── validation.php     # Validation messages (skeleton-managed)
└── id/                    # Indonesian messages
    ├── app.php            # Project-owned application messages
    ├── error.php          # Error messages (skeleton-managed)
    ├── success.php        # Success messages (skeleton-managed)
    └── validation.php     # Validation messages (skeleton-managed)
```

> ⚠️ `error.php`, `success.php`, and `validation.php` are **generated by the skeleton** and will be overwritten by `composer skeleton-update`. Add project-specific messages to `app.php` only.

### Supported Languages

- **English (en)**: Default language, used for development and international users
- **Indonesian (id)**: Local language for Indonesian users

### Translation Categories

Each file name is a category registered via `CategorySource`:

| Category | File | Purpose |
|---|---|---|
| `app` | `app.php` | Project-owned application messages |
| `error` | `error.php` | Error/exception messages |
| `success` | `success.php` | Success messages |
| `validation` | `validation.php` | Validation rule messages |

## 📁 Message Files

### 1. Application Messages (app.php)

**Purpose**: Project-owned messages — the only file you should edit.

#### English Version (`resources/messages/en/app.php`)
```php
<?php

declare(strict_types=1);

/**
 * Application messages (English)
 *
 * THIS IS A PROJECT-OWNED FILE. Add custom messages here.
 * Messages in `error.php`, `success.php`, and `validation.php` are managed by
 * the skeleton and will be overwritten by `composer skeleton-update`.
 */
return [
    /*
     * Add your application-specific error, success, or validation messages here.
     * Example: 'validation.custom_rule' => 'The {field} is invalid.',
     */

    'success' => 'Success',
];
```

**Usage Example**:
```php
// In an action or service — TranslatorInterface is injectable
$successMessage = $this->translator->translate('success', [], 'app');
```

## 🔧 Translator Configuration

### DI Configuration

**File**: `config/common/di/translator-di.php` (actual content)

```php
<?php

declare(strict_types=1);

use Yiisoft\Translator\CategorySource;
use Yiisoft\Translator\IntlMessageFormatter;
use Yiisoft\Translator\Message\Php\MessageSource;
use Yiisoft\Translator\Translator;
use Yiisoft\Translator\TranslatorInterface;

/** @var array $params */

// Core translator binding. Project-owned bindings may be merged from
// config/common/translator.php and can override these defaults.
$projectBindings = \dirname(__DIR__) . '/translator.php';

return array_merge([
    TranslatorInterface::class => static function () {
        $translator = new Translator('en');

        $messageSource = new MessageSource(__DIR__ . '/../../../resources/messages');
        $formatter     = new IntlMessageFormatter();

        $translator->addCategorySources(
            new CategorySource('app', $messageSource, $formatter),
            new CategorySource('validation', $messageSource, $formatter),
            new CategorySource('error', $messageSource, $formatter),
            new CategorySource('success', $messageSource, $formatter),
        );

        return $translator;
    },
], file_exists($projectBindings) ? require $projectBindings : []);
```

### Project Overrides

**File**: `config/common/translator.php` — returns an array merged over the defaults; can rebind `TranslatorInterface::class` (e.g. `static fn () => new Translator('id')`).

### Locale Params

`config/common/params.php` exposes the configured locale under `yiisoft/translator` (from `app.config.language` env var):

```php
'yiisoft/translator' => [
    'locale'         => $_ENV['app.config.language'],
    'fallbackLocale' => $_ENV['app.config.language'],
],
```

### `TranslatorInterface` API (yiisoft/translator)

```php
$translator->translate(
    string|\Stringable $id,
    array $parameters = [],
    ?string $category = null,   // 'app' | 'error' | 'success' | 'validation'
    ?string $locale = null,     // 'en' | 'id' | ... (null = default locale)
): string;

$translator->setLocale('id');              // change default locale (mutates)
$translator->getLocale();                  // current default locale
$translator->withLocale('id');             // new instance with locale
$translator->withDefaultCategory('error'); // new instance with default category
```

## 🚀 Usage Examples

### Basic Translation

```php
// Simple translation
$message = $translator->translate('success', [], 'app');

// Error messages
$error = $translator->translate('http.not_found', [], 'error');

// Success messages
$success = $translator->translate('resource.created', ['resource' => 'Example'], 'success');

// Validation messages
$validation = $translator->translate('required', ['resource' => 'name'], 'validation');
```

### Translation with Parameters

```php
$tooShort = $translator->translate('string.min', [
    'field' => 'name',
    'min' => 3
], 'validation');
// en: "The name field must be at least 3 characters"

$resourceCreated = $translator->translate('resource.created', [
    'resource' => 'Example'
], 'success');
// en: "Example has been created successfully."
// id: "Example telah berhasil dibuat."
```

### Message Value Object

Exceptions and `ResponseFactory` carry `App\Shared\Core\ValueObject\Message` objects that are translated lazily at render time:

```php
use App\Shared\Core\ValueObject\Message;

$message = Message::create(
    key: 'resource.not_found',
    params: ['resource' => 'Example', 'field' => 'id', 'value' => 123],
    domain: 'error', // category; null falls back to the renderer's default ('error')
);

// Rendered as:
$translator->translate($message->getKey(), $message->getParams(), $message->getDomain() ?? 'error');
```

## 🌐 Language Detection and Switching

### Get/Set Locale

```php
$currentLocale = $translator->getLocale();   // e.g. "en" or "id"
$translator->setLocale('id');                // set to Indonesian
$translator->setLocale('en');                // set to English
```

### Per-Call Locale

```php
// Translate to a specific locale without changing the default
$message = $translator->translate('http.not_found', [], 'error', 'id');

// Or create a derived translator
$idTranslator = $translator->withLocale('id');
$message = $idTranslator->translate('http.not_found', [], 'error');
```

### Language from Request

```php
// Get language from Accept-Language header
$acceptLanguage = $request->getHeaderLine('Accept-Language');
// Example: "en-US,en;q=0.9,id;q=0.8"

if (str_contains($acceptLanguage, 'id')) {
    $translator->setLocale('id');
}
```

## 🔍 Best Practices

### 1. **Message Organization**

```php
// ✅ Good: Dot-prefixed, grouped by context
'resource.not_found' => '{resource} data with {field}: {value} was not found',
'resource.already_exists' => 'The {resource} already exists',
'status.invalid_transition' => 'Cannot update {resource} from status "{from}" to "{to}"',

// ❌ Avoid: Deeply nested arrays (message sources use flat keys)
```

### 2. **Parameter Usage**

```php
// ✅ Good: Use parameters for dynamic values
'string.min' => 'The {field} field must be at least {min} characters',

// ❌ Avoid: Hardcoded values
'string.min' => 'The name field must be at least 3 characters',
```

### 3. **Consistent Naming**

```php
// ✅ Good: Consistent naming convention (prefix.context)
'resource.created' => '{resource} has been created successfully.',
'resource.updated' => '{resource} has been updated successfully.',
'resource.deleted' => '{resource} has been deleted successfully.',

// ❌ Avoid: Inconsistent naming
'create_success' => 'Resource created successfully',
'update_done' => 'Resource updated successfully',
```

### 4. **Respect the Skeleton Boundary**

```php
// ✅ Good: Add project keys to resources/messages/{locale}/app.php
// ❌ Avoid: Editing error.php / success.php / validation.php —
//    they are regenerated by `composer skeleton-update`
```

## 🛠️ Maintenance

### 1. **Keep Locales in Sync**

When adding a key to `en/app.php`, add the same key to `id/app.php` (and any other locale) — the key sets must stay identical.

### 2. **Placeholder Consistency**

Ensure `{placeholders}` match across locales — `IntlMessageFormatter` substitutes by name:

```php
// en/app.php
'greeting' => 'Hello, {name}!',
// id/app.php — same placeholder names
'greeting' => 'Halo, {name}!',
```

### 3. **Missing Keys**

`translate()` returns the source message ID unchanged when no translation is found — watch for raw keys like `http.not_found` appearing in responses, which indicates a missing message entry.

---

## 📊 Performance Considerations

### 1. **Message Loading**
- `MessageSource` loads PHP-array message files per category/locale — file reads are limited to `resources/messages/{locale}/{category}.php`

### 2. **Formatting**
- `IntlMessageFormatter` handles `{placeholder}` substitution; keep parameter arrays small

### 3. **Instances**
- Prefer `withLocale()`/`withDefaultCategory()` derived instances over mutating shared state mid-request

## 🎯 Summary

The localization system provides comprehensive internationalization support for the Yii3 API application. Key benefits include:

- **🌐 Multi-Language Support**: English and Indonesian with easy extension for more languages
- **📝 Structured Messages**: Organized by category (`app`, `error`, `success`, `validation`)
- **🔧 Flexible Configuration**: DI binding in `config/common/di/translator-di.php`, project overrides in `config/common/translator.php`
- **🔗 Exception Integration**: `Message` value objects carry `key`/`params`/`domain` through to the response layer
- **🛡️ Type Safe**: `TranslatorInterface` with parameter arrays
- **📊 Maintainable**: Skeleton-managed core messages + project-owned `app.php`

By following the patterns and best practices outlined in this guide, you can create a robust, maintainable localization system for your Yii3 API application! 🚀
